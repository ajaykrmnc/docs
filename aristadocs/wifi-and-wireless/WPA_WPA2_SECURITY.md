# WPA and WPA2 Security Protocols

This document provides a comprehensive overview of WPA (Wi-Fi Protected Access) and WPA2 security protocols, including general information and implementation details in this repository.

## Overview

WPA and WPA2 are security protocols developed by the Wi-Fi Alliance to secure wireless networks. They replaced the vulnerable WEP (Wired Equivalent Privacy) protocol.

| Protocol | Standard | Year | Status |
|----------|----------|------|--------|
| WEP | IEEE 802.11-1997 | 1997 | Deprecated (insecure) |
| WPA | IEEE 802.11i draft | 2003 | Legacy |
| WPA2 | IEEE 802.11i-2004 | 2004 | Current standard |
| WPA3 | IEEE 802.11-2020 | 2018 | Latest |

## WPA vs WPA2 Comparison

| Feature | WPA | WPA2 |
|---------|-----|------|
| Encryption | TKIP (RC4-based) | CCMP (AES-based) |
| Key Length | 128-bit | 128-bit (256-bit optional) |
| Data Integrity | Michael MIC (64-bit) | CBC-MAC (128-bit) |
| Key Derivation | 4-Way Handshake | 4-Way Handshake |
| IE Element | WPA IE (Vendor Specific) | RSN IE (Element ID 48) |
| Security Level | Medium | High |

## Encryption Algorithms

### TKIP (Temporal Key Integrity Protocol) - WPA

- Based on RC4 stream cipher
- Per-packet key mixing
- 48-bit Initialization Vector (IV)
- Michael MIC for integrity
- **Deprecated**: Vulnerable to attacks

### CCMP (Counter Mode CBC-MAC Protocol) - WPA2

- Based on AES block cipher (128-bit)
- CCM mode (Counter + CBC-MAC)
- 48-bit Packet Number (PN)
- Provides confidentiality and integrity
- **Recommended**: Strong security

### Additional Cipher Suites

| Cipher | ID | Description |
|--------|----|-------------|
| CCMP-128 | 4 | AES-CCM with 128-bit key (default) |
| CCMP-256 | 10 | AES-CCM with 256-bit key |
| GCMP-128 | 8 | AES-GCM with 128-bit key |
| GCMP-256 | 9 | AES-GCM with 256-bit key |
| BIP-CMAC-128 | 6 | Management frame protection |
| BIP-CMAC-256 | 13 | Management frame protection (256-bit) |
| BIP-GMAC-128 | 11 | Management frame protection (GMAC) |
| BIP-GMAC-256 | 12 | Management frame protection (GMAC 256-bit) |

## Authentication Modes

### Personal (PSK)

Pre-Shared Key authentication:
- Password-based (8-63 ASCII characters)
- PMK derived from passphrase + SSID
- Suitable for home/small office

```
PMK = PBKDF2(passphrase, SSID, 4096, 256)
```

### Enterprise (802.1X)

RADIUS-based authentication:
- Uses EAP (Extensible Authentication Protocol)
- Unique PMK per client session
- Suitable for organizations
- Requires RADIUS server

## 4-Way Handshake

The 4-Way Handshake establishes the PTK between client and AP:

```
┌──────────────┐                              ┌──────────────┐
│    Client    │                              │      AP      │
│  (Supplicant)│                              │(Authenticator)│
└──────┬───────┘                              └──────┬───────┘
       │                                             │
       │           Message 1: ANonce                 │
       │ ◄────────────────────────────────────────── │
       │         EAPOL-Key(ANonce)                   │
       │                                             │
       │  [Client derives PTK from PMK+ANonce+SNonce]│
       │                                             │
       │           Message 2: SNonce + MIC           │
       │ ──────────────────────────────────────────► │
       │    EAPOL-Key(SNonce, MIC, RSN IE)           │
       │                                             │
       │         [AP derives PTK, verifies MIC]      │
       │                                             │
       │     Message 3: GTK + MIC (encrypted)        │
       │ ◄────────────────────────────────────────── │
       │   EAPOL-Key(Install, GTK, MIC, RSN IE)      │
       │                                             │
       │  [Client installs PTK and GTK]              │
       │                                             │
       │           Message 4: ACK + MIC              │
       │ ──────────────────────────────────────────► │
       │         EAPOL-Key(MIC)                      │
       │                                             │
       │         [AP installs PTK]                   │
       │                                             │
       │  ═══════ Encrypted Data Traffic ══════════  │
       │                                             │
```

## PTK Components

```c
struct wpa_ptk {
    u8 kck[WPA_KCK_MAX_LEN];   // Key Confirmation Key (MIC)
    u8 kek[WPA_KEK_MAX_LEN];   // Key Encryption Key
    u8 tk[WPA_TK_MAX_LEN];     // Temporal Key (data encryption)
    u8 kck2[WPA_KCK_MAX_LEN];  // FT reassoc KCK (802.11r)
    u8 kek2[WPA_KEK_MAX_LEN];  // FT reassoc KEK (802.11r)
    u8 kdk[WPA_KDK_MAX_LEN];   // Key Derivation Key (WiFi 7)
};
```

## RSN Information Element

WPA2 advertises capabilities in the RSN IE (Element ID 48):

```
┌────────────────────────────────────────────────────────────┐
│                      RSN IE Structure                       │
├──────────────┬──────────────────────────────────────────────┤
│ Element ID   │ 48 (0x30)                                    │
│ Length       │ Variable                                     │
│ Version      │ 1                                            │
│ Group Cipher │ OUI (00-0F-AC) + Cipher Suite ID             │
│ Pairwise Cnt │ Number of pairwise cipher suites             │
│ Pairwise     │ List of pairwise cipher suites               │
│ AKM Count    │ Number of AKM suites                         │
│ AKM Suite    │ List of authentication suites                │
│ RSN Caps     │ Capabilities (Pre-auth, MFPC, MFPR, etc.)    │
│ PMKID Count  │ Number of PMKIDs (optional)                  │
│ PMKID List   │ List of PMKIDs (optional)                    │
│ Group Mgmt   │ Group management cipher (optional)           │
└──────────────┴──────────────────────────────────────────────┘
```

## Key Management Suites (AKM)

| AKM | Selector | Description |
|-----|----------|-------------|
| 802.1X | 00-0F-AC:1 | Enterprise authentication |
| PSK | 00-0F-AC:2 | Pre-Shared Key |
| FT-802.1X | 00-0F-AC:3 | Fast Transition with 802.1X |
| FT-PSK | 00-0F-AC:4 | Fast Transition with PSK |
| 802.1X-SHA256 | 00-0F-AC:5 | Enterprise with SHA-256 |
| PSK-SHA256 | 00-0F-AC:6 | PSK with SHA-256 |
| SAE | 00-0F-AC:8 | WPA3-Personal |
| FT-SAE | 00-0F-AC:9 | Fast Transition with SAE |
| OWE | 00-0F-AC:18 | Opportunistic Wireless Encryption |

## Group Key Handshake

The Group Key Handshake updates the GTK for broadcast/multicast traffic:

```
┌──────────────┐                              ┌──────────────┐
│    Client    │                              │      AP      │
└──────┬───────┘                              └──────┬───────┘
       │                                             │
       │    Group Message 1: New GTK (encrypted)     │
       │ ◄────────────────────────────────────────── │
       │                                             │
       │    Group Message 2: ACK + MIC               │
       │ ──────────────────────────────────────────► │
       │                                             │
```

## PMKSA Caching

PMK Security Association caching enables fast reconnection:

```
┌─────────────────────────────────────────────────────────────┐
│                    PMKSA Cache Entry                         │
├─────────────────────────────────────────────────────────────┤
│  PMKID = HMAC-SHA-1-128(PMK, "PMK Name" || AA || SPA)       │
│  PMK = Pairwise Master Key (256 bits)                       │
│  AA = Authenticator Address (AP MAC)                        │
│  SPA = Supplicant Address (Client MAC)                      │
│  Lifetime = Typically 12 hours (43200 seconds)              │
└─────────────────────────────────────────────────────────────┘
```

### OKC (Opportunistic Key Caching)

Extends PMKSA caching across multiple APs:
- AP shares PMK cache with neighbor APs
- Client can roam without full re-authentication
- Uses IAPC (Inter-AP Communication) for synchronization

## Security Considerations

### Vulnerabilities

| Attack | Affected | Mitigation |
|--------|----------|------------|
| KRACK | WPA/WPA2 | Install key only once; use `wpa_disable_eapol_key_retries` |
| Dictionary Attack | PSK modes | Use strong passphrases (12+ chars) |
| PMKID Attack | PSK modes | Use WPA3-SAE instead |
| Deauth Attack | All | Enable 802.11w (MFP) |

### Best Practices

1. **Use WPA3-SAE** when possible for personal networks
2. **Use WPA2/WPA3-Enterprise** for organizations
3. **Enable 802.11w** (Management Frame Protection)
4. **Use strong passphrases** (20+ characters recommended)
5. **Enable OKC** for seamless roaming
6. **Use CCMP/GCMP** ciphers (avoid TKIP)
7. **Keep firmware updated** for security patches
